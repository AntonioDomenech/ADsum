# ADsum v3.2.1 transcription models

ADsum v3.2.1 keeps the complete local workflow and the two optional OpenAI choices introduced in v3.2. The model can be selected before transcribing a new recording or an older item in the Library. The General tab stores the default choice for future runs. Every selectable model now produces speaker-labelled output.

## What each model does

| ADsum choice | Processing location | Speaker labels | Reusable spelling terms |
| --- | --- | --- | --- |
| Local Whisper + Pyannote | This computer | Yes, whole-meeting anonymous labels | Yes |
| OpenAI GPT-4o Transcribe Diarize | OpenAI API | Yes, built into the model | No; the endpoint does not accept vocabulary hints |
| OpenAI GPT Transcribe + Diarization | OpenAI API, two parallel transcription requests | Yes, supplied by the paired GPT-4o diarization pass | Yes; applied to the authoritative GPT Transcribe pass |

`gpt-transcribe` is the newer high-accuracy file transcription model. It accepts prompt and keyword guidance but does not itself return speaker identity. When this option is selected, ADsum sends the same compressed MP3 to `gpt-transcribe` and `gpt-4o-transcribe-diarize` in parallel. The complete `gpt-transcribe` wording is always authoritative. ADsum uses the second result only as a speaker-and-timestamp stencil and aligns the authoritative words onto those turns.

If the two word sequences differ too much for a reliable word-by-word match, ADsum still keeps every `gpt-transcribe` word and distributes those words proportionally across the diarized turns. It adds a visible note to the result so that this best-effort alignment is not hidden. It never falls back to the diarization model's wording. If the API returns no usable speaker segments at all, the run fails instead of saving a transcript without diarization.

Because the two requests run together, the normal elapsed time is governed mainly by the slower request rather than the sum of both request times. It is nevertheless a two-pass cloud option and incurs transcription usage for both models. Actual latency varies with recording length, upload speed, service load, and whether a long MP3 has to be divided into 20-minute upload parts.

The OpenAI API model references are [GPT Transcribe](https://developers.openai.com/api/docs/models/gpt-transcribe) and [GPT-4o Transcribe Diarize](https://developers.openai.com/api/docs/models/gpt-4o-transcribe-diarize). OpenAI's [speech-to-text guide](https://developers.openai.com/api/docs/guides/speech-to-text) explains the supported response formats and diarized file requests.

## Compressed audio and original preservation

After every recording stops, ADsum creates this sidecar in the same meeting directory:

```text
recording-compressed.mp3
```

It is a 32 kbps speech MP3. ADsum validates that the file can be read and that its duration matches the original. Only after validation does it atomically replace an older sidecar. The source WAV is never deleted, rewritten, or used as the transcription upload. All three transcription models read the MP3.

On startup, v3.2.1 scans older meeting directories and creates missing sidecars in the background. Re-running the migration is safe because a healthy existing sidecar is reused. It can also be invoked explicitly:

```powershell
.\ADsum.exe --compress-recordings --result "$env:TEMP\adsum-compression.json"
```

The JSON result reports how many recordings were found, converted, reused, or failed. A failed conversion leaves the source recording untouched and does not leave a partial MP3 under the stable sidecar name.

## General terms

Use the General tab for names and abbreviations that recur across meetings. Enter one item per line, for example:

```text
ADsum
CERTANIA
LucaNet
Microsoft Fabric
```

ADsum removes duplicate terms and stores at most 100 entries of at most 120 characters each. Angle brackets and line breaks inside an entry are rejected. The terms are merged into the local Whisper hotwords and sent as both prompt context and keyword fields to `gpt-transcribe`.

The terms cannot be sent to `gpt-4o-transcribe-diarize` because that specialized API does not accept either prompt or keyword vocabulary guidance. For the combined `gpt-transcribe` option this does not weaken the final spelling: terms are sent to the authoritative wording pass, while the second pass contributes only speaker boundaries and timestamps. The app shows the limitation before a direct diarization-only run, and each saved transcript records whether the terms were applied or unsupported.

## Retranscribing without overwriting

Each model has its own transcript filename:

```text
transcription-local-whisper-pyannote-<topic>.md
transcription-gpt-4o-transcribe-diarize-<topic>.md
transcription-gpt-transcribe-<topic>.md
```

Older unsuffixed transcript files remain visible as legacy versions. Running another model writes a different file, so it does not overwrite the previous model's result. The Library's saved-transcript selector determines which version is previewed, opened, or used for meeting notes.

Every new transcript begins with provenance metadata: the selected model, whether diarization was included, the MP3 source path, the creation time, and whether reusable terms were applied. A combined `gpt-transcribe` transcript additionally records that GPT Transcribe supplied the authoritative wording and GPT-4o Transcribe Diarize supplied the speaker and timestamp structure.

## OpenAI key and privacy boundary

The two OpenAI choices require an API key. A key saved through the app is protected with Windows DPAPI in `%LOCALAPPDATA%\ADsum\settings.json`; `ADSUM_OPENAI_API_KEY` and `OPENAI_API_KEY` remain supported for controlled command-line runs. ADsum does not put a key in a transcript, log, result JSON, release ZIP, or Git commit.

Choosing either OpenAI model sends the compressed meeting MP3 to OpenAI for transcription. The combined `gpt-transcribe` choice makes two transcription requests with that MP3: one for authoritative wording and one for speaker segments. Choosing Local Whisper + Pyannote keeps audio processing on the computer. Meeting-note generation has its own existing OpenAI boundary and remains optional.

## Validation commands

Transcribe one audio file without adding it to the meeting Library:

```powershell
.\ADsum.exe --transcribe-file "C:\path\meeting.wav" --model gpt-transcribe --result "$env:TEMP\adsum-transcription.json"
```

Transcribe and save a model-specific transcript in an existing meeting folder:

```powershell
.\ADsum.exe --transcribe-meeting "C:\path\meeting-folder" --model gpt-4o-transcribe-diarize --result "$env:TEMP\adsum-meeting-transcription.json"
```

Valid model IDs are `local-whisper-pyannote`, `gpt-4o-transcribe-diarize`, and `gpt-transcribe`. If `--model` is omitted, ADsum uses the default saved in the General tab.
